SANITIZATION — PROJECT STRUCTURE & CONTEXT  (read this first; it is the single source of context for new work)
==========================================================================================================

WHAT IT IS
  A Windows tool that finds and removes secrets and personal data from a folder of projects AND from their full git
  history, so private repos can be made public. Two front-ends, one engine:
    Compiled\sanitize.exe      Avalonia 12 GUI (NativeAOT)        - for humans
    Compiled\ai-sanitize.exe   console CLI (NativeAOT)            - for scripts / AI agents (same findings, same ids)
  Stack: C# 14 / .NET 10 (net10.0-windows10.0.19041.0, for Windows OCR), Avalonia 12.1.1 (Fluent, compiled bindings),
  NativeAOT, xUnit. Windows only (DPAPI, WinRT OCR, win-x64).
  Owner's conventions: build.cmd + dev_build.cmd like the sibling repos (KeyPulse); UI look = slate palette of
  C:\FreeVideoStudio; plain-English, "ADHD-clear" UI text.

QUICK START FOR AN AGENT
  Build + test:        dev_build.cmd                      (tests, NativeAOT GUI + CLI into .\Compiled, privacy gate)
  Tests only:          dotnet test tests\Sanitization.Tests
  See what a human sees, as text:
                       Compiled\ai-sanitize.exe scan "C:\Software_Development"          (or: dotnet run --project src\Sanitization.Cli -- scan <folder>)
                       Compiled\ai-sanitize.exe scan <folder> --json                    (machine-readable)
  Fix:                 ai-sanitize fix <folder> --id <id>[,<id>] [--history] [--replace <id>=<value>]
                       ai-sanitize fix <folder> --project <name> --all [--low] [--history]
  Push:                ai-sanitize push <folder> --project <name> --yes [--no-lease]
  Other:               ai-sanitize tools | private list|add|remove | ignore --id | unignore | ignored | recreate-guide | help
  Isolate settings:    set SANITIZATION_SETTINGS_DIR=<temp dir>  (GUI and CLI; never touch the owner's real settings in tests)
  GUI test launch:     sanitize.exe --scan "<folder>"  (+ SANITIZATION_SETTINGS_DIR for a separate instance)

CLI OUTPUT CONTRACT (format=1, stable; extend by adding fields, never rename)
  One record per line; fields "key=value" joined by " | "; newline/CR/tab/pipe inside values escaped as \n \r \t \|.
  SANITIZE  header: version, command, root, projects, critical/high/medium/low counts, seconds
  PROJECT   name, path, git(+branch), remote (github:owner/repo | other | none), uncommitted, unpushed_commits,
            remote_only_commits, needs_push
  F         "  F <id8> | <SEVERITY> | <category> | value= | at=<path>:<lines> | where=file,history:N,commit-message:N,
            commit-author:N,git-remote-config,remote | state=tracked|untracked-not-committed|gitignored-never-committed|
            not-git|history-only|file | can_fix=yes|no|push | fix= or why_not= | replace= | needs=--history | context= | why="
  LOW       count of hidden "probably fine" items (show with --low)      CLEAN  project has nothing
  NOTE      remark (push needed, uncommitted changes, unreadable files)    RESULT fix/push outcome    END | exit=N
  Exit codes: scan 0 = no Critical/High/Medium, 1 = findings, 2 = error | fix 0 = all requested gone, 1 = some remain
  or blocked, 2 = error | push 0 = pushed and no stale remote branches, 1 = refused/failed.
  Ids: first 8 hex of SHA-256(projectPath.lower + "|" + Finding.Key). Stable across scans until the finding changes.
  JSON (--json): JsonReport { command, version, root, seconds, exit, projects[ { name, path, isGit, branch, gitHub,
  uncommitted, unpushedCommits, remoteOnlyCommits, notes, findings[ { id, severity, category, value, path, lines, where,
  state, canFix, onlyOnRemote, needsHistory, fix, replacement, context, why } ] } ], fixes[]? }.

KEY BEHAVIOURS / DECISIONS (don't "fix" these by accident)
  - Fix all never includes Low ("Probably fine"). History rewrite always needs explicit consent (GUI dialog / --history).
  - Git-ignored files ARE scanned and shown as "Never committed (in .gitignore)" (zip-and-share risk) but get no auto-fix
    for whole files.
  - Binaries are skipped unless tracked in git (then only identity rules). Archives / PDF are listed as Low.
  - Office files (docx/xlsx/pptx) are read (text + author fields) in any git state and in history; their findings are
    InsideDocument and never auto-fixed (edit them in Office).
  - After the main pass, Scanner.PostPassAsync promotes Low copies of a Medium+ value and sweeps every working-tree text
    file for it, so one value = all its locations (Finding.Propagated). Learned organisation names are swept the same way.
  - Commit author full names (two capitalised words / Hebrew words, not bots) are reported; fix rewrites them to Dev User.
  - JPEGs are always checked for EXIF GPS (any git state). Fix strips the whole EXIF block in the file and, with history
    consent, in every JPEG blob that has GPS (content-based, in HistoryRewriter).
  - Other people's names and street addresses are NOT auto-detected (too noisy); they come from "My private info".
    YOUR name, GitHub user, e-mails and employer ARE (MachineIdentity). Your first name alone only counts next to
    company / copyright / author / publisher.
  - Our own stand-ins (Heuristics.IsSafeHost / IsSafeEmail / IsGenericUserName) are never reported; *sanitize-map*
    files are skipped. In code files, host names count only inside string literals.
  - Build folders are deleted only when named bin / obj / TestResults, inside the project and untracked;
    .git/lost-found only by its exact path.
  - Values are shown unmasked (owner's choice). Nothing sensitive is written to disk by the app except the encrypted
    settings; the report is never a file.
  - "OnRemote" comes from refs/remotes/* as of the last fetch; the app never fetches on its own before scanning.
  - Release builds refuse to ship binaries containing the builder's user name / PC name.
